// OVERVIEW

A Master's group project developed in partnership with Cornwall Council, designed to teach local primary school students resilience in dangerous situations. The game focuses on the types of hazards children might encounter around Cornwall, turning safety education into an engaging, interactive experience.

// DEV LOG

I was responsible for the project's backend systems. I implemented a singleton GameManager to coordinate game state across scenes, and developed the RTS map alongside the UI and gameplay logic for the firefighting scene. I also built the score system used to track and reward player progress.

// CHALLENGES & LEARNINGS

The module placed a strong emphasis on agile practice, and delivering to a real client brief as part of a team taught me a great deal about agile workflows, iterative development, and collaborating effectively towards a shared goal.

// OVERVIEW

My final year solo advanced game project for my Bachelor's degree, and my most technically ambitious solo undertaking at the time, spanning both programming and 3D art.

// DEV LOG

I developed the core systems, including an inventory and crafting system, ranged combat, and state-driven AI enemies. The standout feature was a physics-based third person player controller with layered animations, splitting the upper and lower body so the character could aim and act independently of their movement.

On the art side, I 3D modelled the low poly characters (rigged using Mixamo), along with the props, weapons and items. Some of the weapons were modelled by one of my course mates, and the vegetation was sourced from a free asset pack.

// CHALLENGES & LEARNINGS

This project taught me the importance of writing clean, maintainable code. I initially managed all player behaviour from a single script, which made it increasingly difficult to add the features I wanted. Working through this problem led me to discover state machines, an approach that has shaped how I structure my code ever since.

// OVERVIEW

A solo project developed for my second year 3D level design module. The brief was to design and build a racing game across three track levels, each featuring its own obstacles.

// DEV LOG

I used Unity Standard Assets for the vehicle assets, logic and AI, Cinemachine for camera behaviour, and EasyRoads3D to sculpt and paint roads directly into the terrain. To add an element of unpredictability, I integrated an animated deer model from the asset store as a free-roaming AI obstacle that turns into a ragdoll on collision with a car.

I designed the UI using assets I created in Photoshop, including a procedurally generated speedometer. The core race systems — lap counting, racer ranking, and reset/respawn — were built on a waypoint-based system to keep everything in sync as vehicles moved around the track.

// CHALLENGES & LEARNINGS

I encountered issues with render textures while implementing a rear view mirror on the GUI, where some trees failed to render correctly through the mirror. It's a problem I'd return to and resolve given the opportunity, and it gave me a useful early insight into the quirks of working with render textures in Unity.

// ABOUT

Roost Runner holds a special place as my first ever solo Unity project, made in the first year of my Bachelor's for a 2D level design module. The brief was open — make a 2D mobile game of our choice — so I went with an endless runner, blending a few different endless runner styles into one.

I sourced the character, enemy, tunnel, obstacle and power-up sprites from itch.io, with a handful made by myself. For enemy navigation I implemented A* pathfinding, and I developed the 2D physics-based player controller from scratch using Unity's old input system, including custom touch interaction detection for mobile.

It was my first taste of taking a game from a blank project to something playable on a phone, and it set the tone for everything I've built since.

A university game jam project from my first year, Trammered was a fast, collaborative sprint where I took on a mix of art and systems work.

I modelled the hand seen holding the beer bottle in front of the player camera, and designed and set up the menu scene — which used thrown bottles to select the menu buttons, a small interactive touch that gave the game character before play even began. I also developed the map puzzle that drove the core of the experience.

// ABOUT

Another game jam project, Dish Dasher was all about quick, satisfying arcade gameplay.

I developed the core mechanics: a player controller with simple horizontal movement driven by pointer position, and a click to swing your bat. Alongside this I built the score system, which rewarded players for stacking and smashing plates.

// ABOUT

Cyber Elite was the first game I ever developed, built for a group university project in my first year — the project that started it all.

I took on a broad slice of the work, developing the level components from the ground up: teleporters with their glitchy shader, falling platforms, level endpoints, and shock areas with their arcing shader. On top of that I built a physics-based player controller, enemy AI, a lives system, and a score system.

Being thrown straight into shaders, AI and physics on my very first project was a steep climb, but it gave me an early, hands-on grounding across the whole stack that I've drawn on ever since.
